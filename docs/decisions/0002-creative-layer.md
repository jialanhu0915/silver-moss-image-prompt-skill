# 0002 创意层独立成层

- 日期：2026-10-23
- 状态：已采纳

## 背景

实际出图反馈与提示词对照发现：现有规则擅长把需求翻译成完整、合规的 caption，却很少主动发明视觉概念。8 张试跑图（含 Layout 茶海报）都「合格但平淡」——元素摆放正确，没有值得记住的关系。原因不在编译规则，而在流程里创意只是润色阶段的一个副作用。

## 选项

| 方案 | 说明 | 结论 |
| :--- | :--- | :--- |
| A. 继续加强润色规则 | 在 `core/caption.md` 里加更多「要有钩子」的措辞 | 否决：契约层会变长，而且说不清何时该发明、何时该保真 |
| B. 新增前置创意层 | 独立 `references/creative/concept.md`，路由按需加载 | **采纳** |
| C. 默认全部重设画面 | 每个需求都先做大胆概念 | 否决：会与用户明确指定的构图、场景、服装打架 |

## 决定

1. 新增 `references/creative/concept.md`，按开放度判定三档模式：忠实 / 增强（默认）/ 自由。模式不写进交付物。
2. 创意手段收敛为七条机制（尺度反转、规则错位、意象具象化、反常主体—环境关系、时间凝固、媒介转化、单一不可能元素），一图一条。
3. 用「一次机制改写」替代「内部构思三个方案」：前者可执行，后者无法验证是否真的发生。
4. 引入执行预算：一个不可能元素 + 落地三件套（参照物、光向、投影）；平面类另走版式与印刷行为分支。
5. 套路组合不禁用，作为「改一条规则」的触发器，标为作者品味。
6. 全部创意判断标【未验证】，不声称能提升出图效果，直到有同参数对照。

## 影响

- 影响文件：`SKILL.md`（路由、流程、自检）、新增 `references/creative/concept.md`、新增 `examples/creative.md`、两份 README、`CHANGELOG.md`
- 不改动三条风格通道、参数档、负面词分层、诊断与 `craft/` 表格。
- 待验证：三例提示词的出图效果；对照测试需关掉 prompt upsampler 以隔离变量。
